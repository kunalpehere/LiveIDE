# Reproducible quality pipeline

Use Node.js 22, matching `.nvmrc`, and npm. `npm ci` installs the committed lockfile and reports dependency mismatches instead of updating it.

## Fresh checkout

Clone the repository into a new directory. No existing `node_modules`, `.next`, generated Prisma client, or local environment files should be needed.

Copy `.env.example` to `.env.local`. Generate an authentication secret of at least 32 characters, set both auth-secret aliases to that same value, and keep `ENABLE_MOCK_DB=false` for the production build. The example MongoDB URL is sufficient for build verification; using the production application requires a reachable MongoDB database. OAuth and AI credentials are unnecessary for these checks. Leave collaboration URL, secret, and application URL empty for these checks, or supply valid independent secrets and secure production URLs; see [configuration](configuration.md).

Run the acceptance checks in order, stopping on any failure:

```bash
npm ci
npm run prisma:generate
npm run lint
npm run typecheck
npm test
npm run build
```

Install the browser once on each machine, then run the final check:

```bash
npx playwright install chromium
npm run test:e2e
```

On Linux CI, use `npx playwright install --with-deps chromium` to install the operating-system dependencies too. Dependency and browser installation require network access.

Type checking runs `next typegen` before TypeScript so it also works without a previous Next.js build or development session.

## Browser test boundary

Playwright starts a fresh development server on port 3100 and a production server on port 3200, and never reuses an existing server. Keep both ports free and run `npm run build` first. The development server explicitly enables the development-only in-memory database and guest authentication, disables AI and collaboration connections, and supplies test authentication settings. The production server uses public build-only authentication fixtures with mock mode disabled. Tests run with one worker because guest sessions share the mock database.

The essential browser checks cover anonymous access redirection, guest sign-in, the starter dashboard, opening a source file, collaborator invitation/removal, and named snapshot creation/deletion. Additional security tests exercise actual isolation/CSP headers, blocked inline scripts, unsupported runtime messaging, and Monaco's TypeScript worker under the production CSP.

Observability checks cover anonymous liveness/readiness endpoints, explicit development mock health, production storage health, and browser error delivery without transmitting its raw contents.

Guest workflow smoke tests exercise the real application UI and server actions in development mode; the anonymous security test also runs against production mode. They do not verify production OAuth, MongoDB connectivity, live WebSocket convergence, or a running WebContainer preview. Deployment verification remains a later milestone.

## CI and failure evidence

GitHub Actions runs installation, Prisma generation, lint, type checking, unit tests, production build, and Chromium smoke tests. It reads the Node version from `.nvmrc` and provides explicit build environment settings without relying on local files. New commits cancel older runs for the same branch or pull request.

- `unit-test-results` contains `reports/unit-tests.xml`, generated by Vitest in CI.
- `playwright-report` contains the HTML report and `test-results` with failed-test screenshots, videos, and traces, including failures on the first attempt.
- Artifacts are uploaded even after a failed check when files exist, and retained for 14 days. Earlier failures may prevent later reports from being created; the failed step's log remains the evidence for installation, lint, type checking, and build failures.

To inspect browser failures locally:

```bash
npx playwright show-report
```

Fix the failing check and rerun it before proceeding. Do not bypass failures or add production mock authentication to make CI pass.

Installation, Prisma generation, lint, type checking, and the production build passed. All 63 unit/integration tests and all four Chromium smoke tests passed. The CI-mode unit run generated its JUnit report, and failed browser attempts demonstrated screenshot, video, and trace generation before the final successful run.
